[3주 차 Day 2] 파일 디스크립터, 프로세스 & 스레드의 이해 요약 노트

1. 파일 디스크립터 (File Descriptor, FD)
----------------------------------------------------------------------
- 개념: 리눅스가 모든 자원(입출력 장치, 소켓, 파일 등)을 파일로 다루면서 
        프로세스에 부여하는 정수 번호표.
- 표준 파일 디스크립터:
  * 0 : STDIN (표준 입력)
  * 1 : STDOUT (표준 출력)
  * 2 : STDERR (표준 에러)
- FD 누수(Leak) 및 관리:
  * OS는 프로세스당 열 수 있는 FD 개수를 제한함 (`ulimit -n`).
  * `open()` 후 `close()`를 지키지 않으면 "Too many open files" 에러로 강제 종료.
  * C++에서는 RAII 패턴(소멸자에서 자동 해제)을 활용하여 수명을 안전하게 관리.

2. 프로세스 (Process) vs 스레드 (Thread)
----------------------------------------------------------------------
[프로세스 (Process)]
- 개념: OS로부터 독립된 메모리 영역(Code, Data, Heap, Stack)을 할당받아 실행되는 단위.
- 특징: RAM 자원의 독립된 그릇 역할. 프로세스 간 상호 침범 불가 (높은 안정성).
- 통신: 별도의 IPC(Inter-Process Communication) 필요 (상대적으로 무거움).

[스레드 (Thread)]
- 개념: 프로세스 내부에서 CPU 점유 및 코드를 실제로 실행하는 일꾼(실행 단위).
- 특징: CPU 코어에 할당되어 작동. 프로세스의 Code, Data, Heap 영역을 공유.
- 독자 자원: 각 스레드는 함수 호출 기록을 위해 독립적인 Stack 메모리만 보유.
- 주의점: 자원 공유로 속도가 빠르나, 데이터 레이스(Data Race) 위험성 존재.

3. 에지 AI / 실시간 시스템에서의 멀티스레드 필요성
----------------------------------------------------------------------
- 병렬 처리: 데이터 수집(Producer)과 연산/AI 추론(Consumer)의 분리로 논블로킹(Non-blocking) 구현.
- 자원 활용: 멀티코어 CPU의 계산 능력 활용을 극대화하여 프레임 드랍(Frame Drop) 방지.

4. 주요 리눅스 모니터링 명령어
----------------------------------------------------------------------
- ps aux      : 시스템의 전체 프로세스 목록 및 CPU/MEM 점유율 확인
- ps -eLf     : 프로세스 내부의 스레드(LWP) 목록까지 세부적으로 확인
- top         : 실시간 프로세스 상태 모니터링 (실행 중 'H' 입력 시 스레드 단위 전환)
